1. Purpose and Scope

GTech Solution Brasil is a digital marketing agency that manages Google Ads accounts for small and medium business clients. All client accounts are linked to our Google Ads manager account (MCC 267-295-5792).

This document describes our internal reporting tool. Its single purpose is to read daily advertising performance metrics from the client accounts under our MCC and consolidate them into an internal web dashboard used by our team and shared with the respective clients.

Reporting-only: the tool performs no write operations. It does not create, edit, pause or remove campaigns, ad groups, ads, keywords, budgets, bids, audiences or any other account entity. It does not upload conversions and does not use the App Conversion Tracking and Remarketing API.

Components

ComponentTechnologyRole
Scheduler / integration n8n (self-hosted, developed in-house) Runs one scheduled workflow per data source. The Google Ads workflow iterates over the client accounts registered in our database and issues GAQL report queries.
Storage PostgreSQL (Supabase) Stores normalized daily metrics. Idempotent upserts keyed by (client, date, platform, campaign) allow safe reprocessing of recent days.
Presentation Next.js web application Login-protected dashboard. Reads only from our own database — it never calls the Google Ads API directly. Derived metrics (CTR, CPC, ROAS) are computed at display time.

3. Google Ads API Usage

3.1 Services and methods

  • GoogleAdsService.SearchStream / Search — daily performance report per client account (only read method used).
  • CustomerService.ListAccessibleCustomers — occasional discovery of accounts linked to the MCC.

3.2 Example GAQL query

SELECT
  segments.date,
  campaign.id,
  campaign.name,
  metrics.cost_micros,
  metrics.impressions,
  metrics.clicks,
  metrics.conversions,
  metrics.conversions_value
FROM campaign
WHERE segments.date DURING LAST_7_DAYS
ORDER BY segments.date

The 7-day window is re-fetched on every run so that retroactive adjustments made by Google Ads are reflected in our database (rows are upserted, never duplicated). cost_micros is converted to currency units (÷ 1,000,000) before storage.

4. Authentication and Security

  • OAuth 2.0: authorization via a Google Cloud OAuth client; the refresh token belongs to an agency user with access to the MCC. login-customer-id is set to the MCC.
  • Developer token and OAuth credentials are stored exclusively in n8n's encrypted credential store on our self-hosted instance. They are never embedded in the dashboard, never exposed to browsers, and never shared with third parties.
  • The web dashboard authenticates users (email/password via Supabase Auth) and enforces row-level security so each client only sees their own metrics.
  • API responses are stored as aggregated daily metrics only; no personal or end-user data is retrieved or stored.

5. Access Model

  • API tool (n8n workflows): internal — accessible only to GTech Solution Brasil staff.
  • Dashboard: GTech staff (all clients) and each client (own data only, after login).
  • The tool is not distributed, resold, or offered to external developers, and the developer token is not used by any software developed by third parties.

6. Error Handling and Compliance

  • Failed runs are logged (status, row counts, error message) and retried; partial failures do not corrupt stored data thanks to idempotent upserts.
  • Rate limits and quotas are respected; requests are batched per account and paced by the scheduler.
  • The API contact e-mail (gabriel@gtechsolutionbrasil.com) is actively monitored and will be kept up to date in the API Center.
  • Required Minimum Functionality (RMF) does not apply, as the tool is reporting-only and does not expose campaign management features.
